    Automatic actions

    When a page with a login form opens, the extension asks KeePass for matching logins at once.

    With this on, every page that has a login form causes one request to KeePass. KeePass may show its access dialog, unless "Always allow access" is on in the plugin options.

    With this off, the extension asks KeePass only when you press a keyboard shortcut. The two options below then do nothing until that moment, because they need the list of logins.

    The list of logins is kept only while the tab is active. It is cleared when you switch tab, reload the page, or lock KeePass.

    Click a username field to see the logins KeePass found. Pick one to fill username and password.

    The list appears only when KeePass found at least one login for the page. Use the arrow keys and Enter, or the mouse.

    On a page without https, the list is red and shows a warning. You can still pick a login, but nothing is filled on its own.

    Needs "Ask KeePass for logins when a page opens". Without it, the list appears only after a shortcut fetched the logins.

    If KeePass returns one login for the page, it is filled into the form at once.

    Only when exactly one login matches. With two or more, nothing is filled and you choose from the list or the toolbar icon.

    Never on a page without https, and never when the form sends to an address without https. On such pages you must pick the login yourself.

    Needs "Ask KeePass for logins when a page opens".

    Keyboard shortcuts

    Press a shortcut while the cursor is in a login form.

    The shortcuts work in the focused form. If the cursor is not in a field, the first login form on the page is used.

    With one matching login, the fields are filled at once. With several, the extension looks at the username already typed: if exactly one login has that username, it is filled. Otherwise a message asks you to choose from the toolbar icon.

    The shortcuts are managed by Firefox. You can change them, or they may be taken by another extension.

    • Fill username and passwordAlt+Shift+U
    • Fill the password onlyAlt+Shift+P
    To change them: open about:addons, click the gear icon, then Manage Extension Shortcuts.

    A small box at the top right of the page tells you why nothing was filled. It closes on its own.

    The box appears for these cases:

    • KeePass has no login for this page.
    • KeePass has several logins and none matches the typed username.
    • No password field was found next to the cursor.
    • The fields could not be filled, for example because the page replaced them.

    With this off, the same text goes to the browser console only.

    Browser login dialogs

    Some sites ask for a login in a window of the browser itself (HTTP authentication, picture below). With this on, KeePass answers it.

    What happens when such a window would open:

    • Page with https and exactly one login in KeePass: the login is sent at once. You see no window.
    • Page with https and several logins: a popup lets you choose one.
    • Page without https: a popup always asks you first, because the login would travel unencrypted.
    • No login in KeePass: the normal browser window appears.

    Security note: with this on, the extension watches every request for such windows. Keep it off if you do not use sites with this kind of login.

    Sites where you chose the fields yourself

    On these sites the extension uses the fields you selected instead of detecting them.

    Sometimes the extension picks the wrong fields on a page, or it finds none. Then you can select them yourself: open the page, click the toolbar icon, and press Choose own credential fields for this page. Click the username field, the password field, and any extra fields.

    The choice is saved for the site (its address without the path). Remove a site here to go back to automatic detection the next time the page opens.

    Advanced

    If a field has a length limit, the filled value is cut to that limit.

    Pages can set a maximum length on a field (the maxlength attribute). By default the extension ignores it and fills the full value, as the browser lets scripts do.

    Turn this on only if a site rejects long values. Risk: a password longer than the limit is cut, and the login fails without a clear reason.

    These settings take effect once KeePass is connected.

    After you sign in on a page, the extension compares the username and password you used with what KeePass has for that page. If KeePass already has exactly this login, nothing happens. If not, the toolbar icon blinks. Click it and choose:

    • New: create a new entry in KeePass with this username, password and page address. For an account that KeePass does not have yet.
    • Update: put this username and password into an entry KeePass already has for the page, for example after you changed your password. With several entries you pick one, the one with the same username is shown in bold. Not available when KeePass has no entry for the page.
    • Dismiss: save nothing.

    New entries go to the group "KeePassHttp Passwords". To update entries, turn on "Always allow updating entries" in the KeePassHttp plugin options in KeePass (Advanced tab). The offer only appears for sign-in pages that send a normal form. Some, for example Google's, do not, and show no offer.

    The settings below control how long the offer stays open.

    seconds

    After this time the offer closes and the typed password is forgotten.

    The time counts only while the tab with the form is the active tab. Switching to another tab closes the offer at once.

    Whatever you set, the extension forgets the password at the latest after this time plus 60 seconds, and never later than 10 minutes. This is a fixed safety limit.

    A value of 0 closes the offer right away, so saving is not possible.

    Advanced: close the offer when the page changes

    After a login, many sites load one or more new pages (redirects). By default these page changes do not close the offer, only the time does. The options below let page changes close it earlier. They are for advanced users; the default behavior works for most sites.

    Count the pages the tab loads after the login, and close the offer when there are too many.

    How the counting works, step by step:

    1. You submit the login form. The offer opens and the clock starts.
    2. During the first ignored seconds, page loads are not counted. This covers the redirects that follow a login.
    3. After that, every finished page load counts as one page change.
    4. When the count goes above the allowed page changes, the next page load closes the offer.

    Example with 2 ignored seconds and 1 allowed change: the login page redirects twice within 2 seconds (not counted). You then open another page on the site (change 1, still allowed). You open one more page: the offer closes.

    The time limit above still applies. The offer closes at whichever comes first.

    With this off, the stored value is -1, which older versions used for "ignore page changes".

    seconds

    Page loads in this time after the login are not counted. 0 counts from the first page load.

    pages

    How many counted page changes are allowed before the offer closes. 0 closes it at the first counted change.

    These settings take effect once KeePass is connected.

    Click the icon to let KeePass generate a new password and put it into the field.

    The password is made by KeePass, with the generator profile that KeePass uses for new entries (KeePass: Tools, Generate Password, profile "(Automatically generated passwords for new entries)"). Change length and characters there.

    The dialog on the page offers two actions: copy the password to the clipboard, or fill it in and copy. After 30 seconds the extension clears the clipboard again, unless you copied something else in the meantime.

    The generated password is not saved in KeePass by itself. After you submit the form, the save offer appears (see Update KeePass).

    KeePassHttp-Link fills your KeePass logins in Firefox and saves new ones, through the KeePassHttp plugin on your own computer.

    Version
    Works with
    Firefox 140 or newer, KeePass 2.x and the KeePassHttp plugin 2.3 or newer (tested with 2.3.1.0)
    Privacy
    Talks only to KeePass on this computer, encrypted with AES-256 and checked with HMAC. Collects no data.

    Remove from Firefox?

    Firefox loses access until you set it up again. KeePass keeps its KeePassHttp entry, delete it there to revoke fully.

    Remove the chosen fields?

    The fields you chose for are removed.

    The extension will detect the fields on its own the next time you open this site.
